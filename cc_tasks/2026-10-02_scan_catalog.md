The operator wants one large table of "all the scans": which any member of the public can run, which need agency involvement and why, how each is done (an existing commercial or open-source tool, or a roll-your-own method over a named protocol), what each provides and which aspect of data readiness it serves, and separate staffing and money cost dimensions with `TBD` allowed. ## Decisions

1. **Rows and sources.** One row per (indicator, scan method). Indicators come from the framework record (`framework/ai_readiness_framework.json`), requirements from the requirements layer (`get_requirements` per indicator; Tool, Precondition and REQUIRES nodes), measurement tier, effort band and cost band from the record, and the Q1 class from `docs/evidence/claims.yaml` (CL-001 onward). Where an indicator has several REQUIRES routes, one row per route (routes are alternatives). Every cell is a record value or the literal `TBD` with a reason in a `basis` column. No cell is filled from memory.

2. **Who can run it.** A closed vocabulary, defined operationally in the README: `public_outside_in` (an unauthenticated client within robots.txt and the harness manners, DD-060, with the identity and rate the cycle used); `agency_enabled` (the agency installs, verifies or turns on something that then produces data: a script, an account, a log export); `agency_records` (the agency must supply records only it holds); `needs_standard` (no standard to test against exists). Anything `blocked` is reserved for access denials per DN-009 decision 5 and is never a value here.

3. **How it is done.** `method_kind`, closed: `built_rule` (already in the harness; name the rule id), `tool_open_source`, `tool_commercial`, `roll_your_own` (name the protocol or method the collector would implement, with its specification), `none_known`. For each non-built method: tool name, licence, URL, the locator of the sentence that says what it does. Corpus first (the Tool nodes and the 264 admitted documents through the `ai-readiness-kg` MCP), then the web. `none_known` is a claim that needs the searches that failed, listed in `basis`.

4. **Agency-enabled instruments, verified.** The operator's hypothesis: one agency-side action (for example verifying a site in a search-engine webmaster console, enabling analytics, or granting access to server or CDN bot logs) may unlock many scans at once. Treat each candidate as a lead to verify, never a fact. Candidates to check at minimum: Google Search Console, Bing Webmaster Tools, web analytics, CDN or WAF bot-management analytics, raw server logs, a robots.txt and sitemap submission. For each: what it exposes (quote the vendor documentation, under 15 words), what verification or install step it needs, who must do it, and which indicators in the record it would serve, joined through the requirements layer where a node exists and marked `proposed_link` where it would need a new node. An enabler whose capability a source does not establish is `unsupported`.

5. **Rollup views, generated from the table, not authored.** (a) enabler or tool to indicators unlocked: count, list, and the greedy set cover (the smallest set of tools and enablers that covers the most currently unmeasured indicators, in order); (b) framework criterion by `who can run` matrix; (c) staffing band by cost band matrix. Emit each as CSV and as a Markdown table. No view ranks by value, impact or return; DN-009 decision 3 holds. Order is by count or by band only.

6. **Cost, two dimensions.** `staffing_band` and `cost_band` are separate columns. Carry the record's existing notional effort and cost bands with `basis: notional_record`. New values only with a cited source; otherwise `TBD`. Do not invent a band to fill a blank.

7. **Benefit and aspect, from the record.** `serves` is the readiness aspect the indicator belongs to, taken from its criterion in the framework record (the four criteria plus the three added); `why` is the indicator's own stated rationale from the record or `TBD`. Nothing paraphrased beyond the record's words.

8. **Cheap-pass exposure.** One column, `cheap_pass`: whether the pass condition can be met without serving a reader, with the basis (a rule module comment, a control fixture, or a described case). `TBD` is allowed. Before filling it, search prior art on metric gaming in composite indicators (Goodhart, Campbell, the OECD/JRC composite-indicator handbook already in the corpus) and cite what is found in the README; do not reason from first principles where a named result exists.

9. **Reader gate (DN-009 d7).** A fresh subagent given only the README and the three rollup tables writes five sentences on what the catalog says about what the public can scan, what needs the agency, and the one enabler that unlocks the most, and the one action it would take. The RESULT quotes the five sentences. If the subagent cannot, the task fails before reaching the operator.
