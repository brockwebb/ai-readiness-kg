## 4. Decision 3 — numerals, and the thing that failed twice

The bare-numeral lint already skips table rows and the exempt region, so the generated fragment needs no new exemption; `build_l0_report` reported `bare_numerals_in_prose: []` on every build. **The PDF numeral-multiset gate failed twice** before it passed, and neither fix touched the gate:

1. Autolinked URLs: typst breaks link text at every punctuation mark, so `jos-2021-0013` came out `2021-` / `0013`, which the gate's hyphen join reads as `20210013`. Plain-text URLs did not cure it — typst also breaks plain text before a digit after `-` or `.`, and breaks anywhere inside a 250-character query string.
2. The fix is a typst show rule in `build_report_pdf.render`, through the `header-includes` hook the build already uses: every compound numeral (digit runs joined by `-` or `.`) and every run of four or more digits is boxed, so a numeral never straddles a line. A first version boxed *every* numeral and failed the gate the other way — pypdf emits a box as its own line, and the page-number strip swallowed 51 lone integers from table cells — which is why short integers are left unboxed. Column widths are declared on the fragment's separator row so the Source column gets 46% of the page rather than a fifth.
