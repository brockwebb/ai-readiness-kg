**§2.a, department → inventory URL, by named source:**
1. **Domain: CISA's `.gov` registry.** `https://github.com/cisagov/dotgov-data`, file `current-federal.csv` (columns include `Domain name`, `Agency`, `Organization`). Fetch the raw CSV once, retain it as evidence with digest, and resolve each Tier A parent department and each Tier B department to its domain by exact match on `Agency` (e.g. "Department of Labor" → `dol.gov`). Where an agency name in the roster does not match a registry `Agency` string exactly, record the normalised match rule used (case-fold, strip "U.S.") and the registry row; never a hand-typed domain. The Federal Reserve Board is not an executive department; it is in the registry as its own agency, and if it is not, record `not_in_dotgov_registry` and use the host the roster already has from the ICSP source page (`www.federalreserve.gov`), citing that provenance.
2. **Inventory URL: the data.gov harvest source registry.** `catalog.data.gov` (CKAN with the harvest extension) publishes each organization's harvest source, which is the authoritative record of where the government itself reads that department's `data.json` from. Query `https://catalog.data.gov/api/3/action/organization_list?all_fields=true` and, per organization, `https://catalog.data.gov/api/3/action/harvest_source_list` or the organization's `/harvest` page if the action needs auth; retain the responses. The inventory URL for a department is the harvest source URL of type `datajson` for that organization. `https://<domain>/data.json` from step 1 is the cross-check: fetch both; record `inventory_url_agrees` / `inventory_only_in_harvest_registry` / `inventory_only_at_domain_root` / `no_inventory_found` per department. Each of those four is a tier-0 fact about the department and is registered as a count (`fss_departments_inventory_*`).
