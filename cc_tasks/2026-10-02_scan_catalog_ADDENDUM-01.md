# ADDENDUM-01 to `2026-10-02_scan_catalog.md`: value by effort, actions, and the front door

**Date:** 2026-10-02 **Status:** AMENDS the base task. Does not supersede it. Read before any step.
**Authority:** `docs/design/2026-10-02_DN-010_value_effort_matrix_decision_support.md`, operator decision of 2026-10-02. Estimated spend rises to about 10M tokens (Opus); the base header is immutable and stays as written.

## Added decisions

10. **Effort and value, on the DN-010 arrangement.** Add columns `staffing_band`, `cost_band` (1 to 5 or `TBD`), `effort_level` (the higher of the two when both are known, else `TBD`), `value_rating` (1 to 5 or `TBD`), `value_basis` (`evidence`, `rubric`, `TBD`), `evidence_grade` (`established`, `plausible`, `unevidenced`), `rated_by`, `operator_override` (empty). Write the value rubric into the README FIRST, citing the prior art you find on prioritization matrices (corpus first, then the web), and rate every row against it. Carry the record's existing notional bands as `basis: notional_record` and map them onto 1 to 5 with the mapping stated; where the map is not defensible use `TBD`. Value never enters the score, a rank or a bound, and the README says so once at the top.

11. **Actions, not only scans.** A scan that fails must lead somewhere. Add `docs/catalog/actions.csv` and `.md`: one row per Action in the record's prescription layer (`get_prescriptions`; the 23 Census actions in the `hours` band and any others), with the indicators it moves, the bound each moves under equal weights (Q6 of the evidence map, CL-055 onward, not recomputed), `what_would_have_to_be_done`, who does it, the same effort and value columns, and `cheap_pass`. For each action, `evidence_grade` is searched, not assumed: whether the action does what it claims is a claim needing a source. Include, as named rows if the record has no Action for them: a well-formed `robots.txt` (cite RFC 9309 and the crawler operators' published documentation for the user agents the harness probes) and an `llms.txt` (cite the proposal and any measured consumption by AI systems; if none is found, `unevidenced`, with the searches listed). Report whatever the evidence says, including that it may not support the operator's expectation of high value for `llms.txt`.

12. **The matrix.** Generate, from the two tables, a five-by-five effort-by-value grid of counts with the row ids in each cell, for scans and for actions separately, plus a flat list of the cells with effort at most 2 and value at least 4 ("quick wins"), and of those with effort at most 2 and value at most 2 ("clear them out"). Rows with a `TBD` axis are listed beside the grid with the reason. The rendering carries the one-line label DN-010 requires. Emit CSV and Markdown; no ranking beyond the cells.

13. **The front door.** For each of the 16 bodies and the tier C comparators, from the stored observations only (no new request), record whether response headers or a challenge page name a CDN or bot-management vendor (for example Cloudflare), with the observation ids as locators. Write the per-body result in the README under "what stood in front", and a column `front_door_observed` in a small table. Make no inference about why any finding was a denial; the operator has asserted that Census uses Cloudflare, so a body with no such observation is `not_observed_in_record`, not "no CDN".

14. **Write set additions:** `docs/catalog/actions.csv`, `docs/catalog/actions.md`, `docs/catalog/rollups/matrix_scans.csv`, `docs/catalog/rollups/matrix_actions.csv`, `docs/catalog/front_door.csv`, plus tests that assert the closed vocabularies for the new columns, that every rated row has a `value_basis`, that no `value_rating` or `value_basis` column is read by any score, rank or bound code path (a static test over the scoring module imports), and that the grids' cell counts equal the row counts. Reader gate (decision 9) now also reads `actions.md` and the grid, and its five sentences must name the quick-win cell's content or say it is empty.
