## 6. Every premise wrong

**(a) Removing `G1-D` from `params.tier0.legs` would not have removed it from the instrument,
and this is the most consequential correction.** Decision 2 says to remove the leg from
`params.tier0.legs` "and from any product-leg list". But a tier-A `home` surface never took its
legs from that list: `run.targets` gives `home` and `flagship` alike the framework set derived
from the rule REGISTRY (`CONTROL_LEGS`), and only Tier C reads `tier0.legs`. Doing exactly what
decision 2 says would have left G1-D judged on all sixteen agencies' home pages while the
published matrix no longer showed the column — the worst shape: a measurement still being taken
and no longer displayed. The withdrawal is therefore **surface-kind scoped**, declared in
`params.tier0.legs_withdrawn` with its construct, its reason and its DD, and read by a new
`run.withdrawn_on(params, surface_kind)`. Recorded as DD-066 §4.

**(b) There is no `withdrawn` state on the Result state machine.** ADDENDUM_01 says the
published G1-D Results "move to `withdrawn`". `seldon/domain/research.yaml` gives Result
`proposed → [verified, rejected]`, `verified → [published, stale]`, `published → [stale]`,
`stale → [verified]`. `stale` is the reachable state from `published` and is the machine's own
word for a value that stands as measured and is no longer the current instrument's answer; it
is also reversible, which a withdrawal of a correctly-taken measurement ought to be. The reason
goes on the artifact as `withdrawn_reason` / `withdrawn_by`. Adding a state to a machine several
projects share, to name something a property already names, would have been the heavier and
worse change.

**(c) "Every other published Result keeps its value and state" — two more moved, for a
second-order reason.** `surface_disagreements` counts cells where a body's home and flagship
surfaces answer the same host-level check differently, **over the surface-judged tier-0 legs**.
That was five legs while G1-D was one of them and is four now, so the count fell from 17 cells
across 8 bodies to 12 across 6. A name binds once (AD-028), so the published pair could not be
re-bound: they are withdrawn at their true five-leg values and the new comparison is registered
as `..._over_four_legs_...`. This is the same remedy DD-056 and `leg_results(family=…)` already
use for a name that did not carry the dimension it varied on — and the latent defect is the
same one: the original names said nothing about which legs were compared. Found by the
registrar refusing to re-bind, which is the guard working.

**(d) The report's prose had three more G1-D dependencies than the addendum enumerated.** The
frame's "## The six checks" heading and its **G1-D** definition paragraph (a column the document
no longer has), the matrix section's "The five surface-judged checks are read from each body's
home page" (now four), and the Tier C paragraph's "All three also fail the uncertainty check"
(a verdict the matrix no longer shows). ADDENDUM_01 says "every other paragraph stays
verbatim"; leaving these would have shipped a report whose prose contradicts its own tables,
which is the hand-wave the addendum exists to remove. All four edits are minimal — a numeral, a
deleted paragraph, a deleted sentence — and none touches a finding. **And a typed table row
had one cell too many:** `| *this report* | \- | \- | \- | \- | \- | \- |` was hand-written under
the tierA include for a six-leg header and now has five dashes.

**(e) §5's `grep -c "G1-D"` clause is not satisfiable as written, and should not be.** It asks
that the built markdown carry G1-D only in the withdrawal sentence and the DD citation. The
built markdown carries it **83** times: **1** in the body's prose (the withdrawal sentence,
which also carries the single DD-066 citation) and **82** in the **method appendix's tables** —
the "which rule judged this cycle" table (2) and the per-check sources appendix (80). Both are
the record of what the measured cycle measured, and decision 2 is explicit that the history does
not move. Stripping them would be rewriting the record of cycle 4. The clause's intent — no
G1-D column, no G1-D rate, no G1-D in the report's argument — is met and is asserted by the
protected-paths check, which counts the body's prose and the appendix separately.

**(f) The graph spells it `G1`, not `G1-D`.** `Finding.indicator_code` carries the SPEC code;
the leg name lives on the payload and in `params.tier0.legs`, and the rule is `RULE-G1-D-v1`. A
§0 query written against the leg name returns **zero rows** and reads exactly like a leg that was
never measured — which is how this session's first attempt read. Every query here keys on
`rule_id`.

**(g) Three standing tests compared a STORED artifact against TODAY's parameters**, and a
