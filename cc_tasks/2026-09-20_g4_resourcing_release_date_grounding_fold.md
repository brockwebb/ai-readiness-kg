## 0. What was checked before this was written

**A. G4.** The previous task located G4's two sources and found they support one clause of three. Whole-document searches of SPWP 46 (168,922 characters) and FCSM 19-01 (439,613) return zero hits for `authorit`, `statut`, `issuing`, `provenance`. "Issuing authority" and "statutory mandate" as metadata carried on the product rest on nothing cited. No Issue was filed because my rule filed one only for outcome (c); the rule was too narrow. The corpus already holds the documents that define such fields: `dcat-us-1-1-schema` (cited by A3, A8, D4), `dcat-us-3-dataset-schema`, `dcat-us-3-overview`, `w3c-dcat-3` (A6, B2), `w3c-prov-o-ontology` (D3), `schema-org-dataset` (A6). None is cited by G4. Prior art, to be confirmed against those substrates and not taken from this sentence: DCAT-US 1.1 requires `publisher`, `bureauCode` and `programCode` on every dataset (issuing authority as a carried field); DCAT-AP defines `dcatap:applicableLegislation` (`http://data.europa.eu/r5r/applicableLegislation`, range `eli:LegalResource`, on Dataset, Distribution, Data Service) as the link from a dataset to legislation. DCAT-AP is not in the corpus. Its stated meaning is the legislation a resource falls under or complies with, which is adjacent to "the mandate the data are collected under" and not the same claim.

**B. The release date.** `scripts/build_l0_site.py:496` sets CITATION.cff `date-released` to `datetime.now`, `:526` does the same for Zenodo `publication_date`, `:871` for the sitemap `lastmod`. The previous task's report rebuild therefore moved the release date of record from 2026-09-19 to 2026-09-20 in `CITATION.cff`, `.zenodo.json` and their `docs/data/` copies, and pushed. A locator edit re-dated the release. Prior art: reproducible builds take every embedded date from the source, never the clock (`SOURCE_DATE_EPOCH`, reproducible-builds.org); Zenodo and the Citation File Format both define the release date as a property of the version, so it moves when the version does and not otherwise.

**C. Grounding.** `grounding.normalize` is NFKC, hyphenated-line-break join, whitespace collapse. NFKC does not fold U+2019 to U+0027 nor U+2014 to a hyphen. The previous task met both: one G4 quote grounds in the Docling rendering and not in pypdf's over an apostrophe, another was dropped over em dashes. Models commonly emit straight quotes for a source's curly ones, so the extraction gate may be quarantining verbatim spans over punctuation alone. How many is unknown. Prior art: W3C Web Annotation `TextQuoteSelector` and the fuzzy anchoring built on it treat typographic punctuation as a normalization class; Unicode's confusables and compatibility foldings are the standard tables. **This task measures. It does not change `normalize`**: that function decides every grounded write in the graph, and changing it is a decision made on a number.
