## 0. Prior art, on disk and in the operator's own repos

The pattern exists twice already and this task copies it rather than designing a third: `/Users/brock/GitHub/fss-policy-kg` (its MCP: a corpus overview to call first, `get_document`, `get_definitions`, `get_obligations`, `get_concept_mentions`, `get_lineage`, `check_currency`, `search_text`, and a read-only `run_cypher` escape hatch), and the Census MCP server (pragmatics; the shape of a tool that returns judgment with its basis). Read both servers' tool definitions and their read-only Cypher guard before writing a line here, and name in the RESULT what was copied and what had to differ. FastMCP in Python, as those use.

The graph this serves: 171 nodes and 325 edges after the prescription layer; `AssessmentIndicator`, `Construct`, `Definition`, `MeasurementSpec`, `Rule`, `Document`, `Action`; the scan projection's `Observation` and `Finding` nodes with evidence locators under `corpus/evidence/scan/`; the cycle of record declared at `docs/reports/publication.yaml:snapshot_cycle`.

**Decisions taken here (operator overrides later):**

1. **Read-only, and the guard is the one fss-policy-kg already has.** The `run_cypher` tool refuses any statement that is not a read (`CREATE`, `MERGE`, `SET`, `DELETE`, `REMOVE`, `CALL … write procedures`, `LOAD CSV`); the refusal is a returned message, not an exception. A test drives every write verb through it.
2. **Eight tools, each returning locators with every fact.** A result without a source locator (record path and node id, matrix path and cell, evidence file and hash, document doc_id and section) is a defect; the tests assert the locator fields are present and resolve.
   - `get_overview()`: the call-first tool. Counts by tier and basis, actions and edges, the cycle of record and its date, bodies on it, and the round-trip gate's last status. From the record and `publication.yaml`, not from opinion.
   - `get_indicator(code)`: definition, construct, spec, rule id and version, tier, basis, `tier_source`, notes, the actions that remediate it, and the pass/fail count on the cycle of record.
   - `get_body(name)`: verdict per leg on the cycle of record with the Finding id and evidence locator per cell, plus a one-line summary (n failing of n judged).
   - `get_prescriptions(body=None, leg=None)`: `scripts/prescriptions.py` as a tool, same output fields, ranked by `bodies_failing_now` when neither argument is given. The pending bands print as `pending`, never as a number.
   - `get_evidence(finding_id)`: Finding → Observation → evidence file path, sha256, fetch timestamp, rule version, the reason string.
   - `get_document(doc_id)` and `search_text(q)`: over definitions, indicator text, action descriptions and technique quotes, with doc_id and section on every hit.
   - `get_cycle_of_record()`: name, matrices, `derived_from_params_hash`, judgement hash, the supersession note (DN-004: `_rj3` moved no verdicts).
   - `run_cypher(query)`: decision 1.
3. **The server reads Neo4j for graph questions and the record for record questions**, the way `prescriptions.py` does: the record is the source of truth; the projection is valid while `tests/test_framework_projection_roundtrip.py` is green, and `get_overview` reports that status so a client knows whether Cypher answers are current.
4. **Registered in this repo's `.mcp.json` for Claude Code and documented in one page** (`docs/design/mcp_over_the_graph.md`): the tool list with one example call and its actual output each, generated by running the tools, not typed. The operator wires it into Claude Desktop by hand; that is a one-line config the RESULT quotes.
5. **No natural-language front is built.** The MCP client is the front; that is the whole point of the shape (DN-005 §2.4). A test that asks each tool one question and checks the locators is the acceptance test, not a chat transcript.
