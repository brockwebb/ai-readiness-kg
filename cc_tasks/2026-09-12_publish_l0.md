**Decisions taken here (operator overrides later):**
1. **What publishes, machine-first.** The tree Pages already serves (the graph page lives there; find it, do not create a second site) gains an L0 index that links, in this order: the matrices as JSON and CSV, the per-check source appendix as JSON, the tagged Results as JSON (name, value, state, generating artifact), the framework record, the corpus manifest, then the built markdown and the PDF as views. One sentence on the index says the PDF is a projection of the data above it. Every file linked is generated by an existing builder; nothing is hand-written except the index's fixed text.
2. **The self row.** The published host carries `robots.txt` admitting the identified AI clients the instrument uses, `llms.txt`, and a sitemap, generated and committed. After the tree is live at its current URL, the six tier-0 legs run against the published host with the identified client through the normal harness path (`run.py` with a one-host frame), verdicts registered under `self_l0_<leg>_<cycle>` names, and the index prints the six verdicts outside the agency matrix with the reference-host caveat. A `fail` on the self row is reported and left visible; it is not fixed in this task, because fixing it after scanning is the thing the instrument measures agencies for.
3. **Result states.** Every Result the report tags: fresh re-derivation from its generating artifact; if the value reproduces, `proposed → verified` with an event; then `verified → published` in the publish commit with an event carrying the commit hash. A tagged Result that does not reproduce is a stop. If the registry has no state-transition verb, §1 stops and the RESULT says what it would need; publication waits.
4. **Version and citation.** Title page carries the snapshot cycle (`scan_2026-09-10_rj2`), the git commit, and the build date. `CITATION.cff` and `.zenodo.json` are generated from the manifest-style metadata (title, authors, version, date); no DOI is minted and no Zenodo call is made.
5. **Pages configuration is not touched.** If the tree is not being served, the RESULT says which setting the operator must change and stops before decision 2 (the self-scan needs a live host); decisions 1, 3, 4 still complete.

**Zero edits to:** rule modules, harness runtime, stored payloads, cycle evidence, targets, figures, section prose, the skeleton, the record, `corpus/`.
