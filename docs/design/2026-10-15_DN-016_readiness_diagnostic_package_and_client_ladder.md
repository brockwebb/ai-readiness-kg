# DN-016: the readiness diagnostic package, and the client ladder

**Date:** 2026-10-15
**Status:** Active. Operator rulings 2026-10-15 (working-group meeting 2026-10-16).
**Depends on:** DN-015 (the instrument, the four states), DN-005 (the framework is the goal), the audit `cc_tasks/2026-10-15_instrument_specification_audit_RESULT.md`.
**Does not change:** any measurement, threshold, rule or cycle. This note changes what is written in the graph about the instrument, and what is rendered from it.

## 1. Why

The working group has an imagined picture of the measurement: a crawl of every page, a security event, a verdict delivered by one person against private criteria. The real measurement is sixteen checks against published criteria, one request each, from the least privileged client the public has, over a named roster, with the results going to the agency and not the public. Nothing in the project states this in one place in plain language, and the instrument's own content (hypothesis, where we look, pass and fail definitions, sources) lives in `assessment/instrument/RULE-*.yaml`, outside the graph that is supposed to be the source of truth. The package replaces the imagined picture with the published method, and the entries move into the graph so every render is a query.

## 2. Rulings

1. **Vocabulary.** The whole run is a *readiness diagnostic*. The unit is a *check* (DN-015's noun). The thing that runs it is the *public client*. "Scan", "probe", "crawl" and "audit" do not appear in any rendered product; the code keeps `scan` in its paths. The rendered terms live in the vocabulary file so all renders change together.
2. **The client ladder.** Rung one: anonymous, keyless, honors robots, rate-limited. Rung two: registered as any member of the public registers, key presented. A key obtained by open registration is a good-faith handshake, not a block (FAIR A1.2: the protocol allows for an authentication and authorization procedure where necessary). A refusal at rung one with a pass at rung two is reported as both, because both are true about the public experience. A rung that needs an agency to grant what a citizen cannot obtain is not on the ladder; it stays "not measured, refused".
3. **Rung two is specified now and measured later.** The package lists every surface in the roster that takes a key and whether its registration is open, from the record's Tool and Precondition nodes (task 8f8861ce). The first measured rung-two cycle is its own task with its own pre-registration. No rung-two result is shown before one exists.
4. **The entries live in the graph.** Every field of a `RULE-*.yaml` entry that a reader needs (plain name, the question, where we look, what the client does, what pass, partial, fail and not-measured mean, why it matters, the sources by corpus id, the state) is written to the MeasurementSpec through `scripts/framework_writeback.py::save`, with `evidenced_by` edges to the corpus Documents the entry cites, and projected. INSTRUMENT.md, the summary's page two, the dictionary and the deck are renders of that node set. The YAML remains the authoring surface; the graph is what answers questions.
5. **Formats.** The package ships as Word (.docx) and PowerPoint (.pptx). No PDF for this product; this overrides the reports rule in CLAUDE.md for the package only, and the part of that rule that matters is kept: one script, one query, both files, the Markdown source hash recorded in the build report.
6. **Review.** Opus 4.8 authors (role `author`). Opus 5.5 reads every entry as the most hostile agency representative in the room and writes the objection. An entry that draws the same objection twice is rewritten. Objections and rewrites go in the RESULT.

## 3. The package

**Page one, the preface: what the public client is and what it never does.** The exact user-agent string, so a security team can find every request in its logs. One request per check per surface; the standing rate limit quoted. Robots honored, with the count of surfaces not fetched because of it on the cycle of record. No credentials at rung one; a public key at rung two. No CAPTCHA, no form submitted, no script executed, nothing fetched beyond headers and the page body. The roster, by body and surface, with where we look for each. The four states, with "not measured" and its three reasons. The two rungs. One sentence on what the diagnostic is not: it does not test whether an agent completed a task; that is a later level of the framework.

**The dictionary: sixteen entries.** Per check, in this order: plain name; the question in one sentence; where we look (seeded location and product page); what the client does, described as a person would describe one request; what passing looks like; what partial, fail and not-measured look like; why it matters, naming the source in plain words (an OMB memo, a W3C practice, a FAIR letter) or stating "this is the project's rule"; who else runs this check, where the audit found one; what rung two changes, if anything. A4 and A11 are shown as declarations read but not scored; A12 as under review.

**The rung-two listing.** Body, surface, key required, registration open to the public (yes, no, to be confirmed), source of that fact.

**The deck.** The preface as two slides, the roster as one, the ladder as one, the sixteen checks as one slide per criterion group, the rung-two listing as one, and what comes next as one. Calibri, white background, black or grey text, orange accent only.

### External

The library holds FAIR. Its FAIR search returns three works that cite Wilkinson et al. 2016 (`10.1038/s41597-022-01710-x`, `10.1038/s42003-026-10694-y`, arXiv 2003.02320). A1.2 ("the protocol allows for an authentication and authorization procedure, where necessary") grounds the client ladder's second rung (§2 ruling 2), and the corpus document is `wilkinson-2016-fair-guiding-principles` (internal receipt below).

The library holds none of the other five sources. Each search below returned only off-topic rows: web-agent benchmarks, retrieval "EM" scores, robot-arm papers, LLM self-verification, and the "Menlo Research" and Menlo Park affiliations. Each is therefore recorded as a failed library search, and the source is cited from knowledge:
- **Google Lighthouse.** Anyone can run its automated audits against a named page. The criteria are published, and an audit can come back pass, fail or not applicable. It is the nearest working precedent for a public-client readiness check.
- **W3C WCAG-EM** (Website Accessibility Conformance Evaluation Methodology). It samples a set of pages and checks them against published criteria. It keeps "not tested" and "not present" as states distinct from fail.
- **RFC 9309** (Robots Exclusion Protocol). This is the rule the client complies with.
- **Power, M. (1997), *The Audit Society: Rituals of Verification*.** It describes how institutions respond to external measurement, and it grounds the preface's choice to publish the method before any result.
- **DHS (2012), The Menlo Report.** It is the research-ethics frame for passive and active internet measurement.

These five are named in the dispatched task's hostile reading. They are not grounds for any measurement.
