# The evidence map

`claims.yaml` holds every claim the one-page summary and the brief will make, each written down with its evidence before any prose is drafted (DN-009 decision 2, `docs/design/2026-10-02_DN-009_deck_rejected_evidence_map_first.md`). Each entry under `claims` has: `id` (`CL-NNN`, stable: a regenerated entry keeps its id, and an id is never reused); `key` (the deterministic name the generator matches ids on); `question` (the task question that produced it); `text` (one sentence, the claim as it would be made); `status`, one of `record` (established by the record: a finding, Result, document or indicator, with a locator), `prior_art` (established by cited literature), `needs_measurement` (the summary would need it, and the record does not hold it yet) or `unsupported` (used only with the search that failed); `evidence`, a list of `{kind, id, locator, note}` where `kind` is `finding` (a Finding id, located at its line in `events/cycle-<cycle>.jsonl`), `result` (a Seldon Result artifact id), `document` (a corpus doc id, located at its first `manifest_add` event), `indicator` (a framework record node id) or `query` (a named computation in `scripts/build_evidence_map.py::QUERIES`); `numbers`, the source of every numeral in `text` (identifiers, dates, legs and HTTP statuses are backticked and are not prose numbers); and `source_task`, the task file that wrote the entry. The `record` and `needs_measurement` entries whose `source_task` is `cc_tasks/2026-10-02_evidence_map_record.md` are generated by `scripts/build_evidence_map.py` from the framework record, the cycle of record (`docs/reports/publication.yaml: snapshot_cycle`), its event shard and the projection, and `--check` compares them byte for byte; every other entry is carried through untouched. `tables` holds the rows behind the claims: the measurement boundary (Q1; what blocks each unmeasured indicator, classed `open_tooling`, `funding`, `no_standard` or `agency_cooperation` in the order an outside party could remove the blocker, plus `not_blocked` where the record says nothing stands between the indicator and a verdict), findings by body (Q2; `access_denial` means an HTTP `401`, `403` or `429` (RFC 9110 §15.5.2 and §15.5.4, RFC 6585 §4), a robots.txt disallow (RFC 9309) or a connection reset by the host, as the harness's error map `assessment/harness/scan/errors.py` records them; that map has no class for a bot challenge served with HTTP `200` or for `ECONNREFUSED`, so neither is counted; `absence` means the record, field or file the rule asks for is not served, which DN-009 decision 5 says is not "blocked"), admissions by date (Q3), and the numbers that differ from the brief pack (Q5).
