# The instrument specification: every check as a hypothesis

Generated by `scripts/instrument.py` from `assessment/instrument/RULE-*.yaml` under DN-015 (`docs/design/2026-10-15_DN-015_instrument_specification.md`). Each row answers the operator's four questions: is it a valid question; what behavior a published source expects; what test the harness runs and whether it is the recognized one; and what a result does and does not claim. A check is `specified` only when every branch of its rule rests on a published behavior; page two of the summary shows only `specified` checks that are not declarations.

Terms used throughout: **SI client (SI system)**: a system that finds, reads and uses data on its own, such as an answer engine, an agent or a retrieval pipeline; the project's term for what is elsewhere called an AI system; **data page**: an agency's own web page for one data product, the page the harness measures (also 'product page' in rule code); **harness**: this project's scanner: an identified, robots-compliant HTTP client that fetches the pages and records what it met; **cycle of record**: the scan whose results the published grid is built from (here scan_2026-10-07_composite_d); **recorded location**: an address for an agency's API, terms, changelog or inventory that the harness was given, read from the agency's own pages or seeded from a named source; **error / not measured**: the harness could not observe: an access denial, its own robots compliance, an absence it could not confirm, or a server or network error; never a fail; **leg**: one check as the harness runs it, named by its indicator code (A1, D4); each leg has one rule, and the codes in a test field name other legs whose fetches this one reuses; **rule / branch**: the versioned code that turns observations into a verdict; a branch is one way the rule can reach a verdict, with its own reason text; **Observation**: one recorded fetch (request, response, parsed content) that a rule judges; **surface**: the page a verdict is about: a data page, or for site-level checks the agency's home host; **body**: the agency, as the harness's records name it; **complete search**: an absence is reported as a fail only when every candidate location was observed and every named source searched; otherwise the verdict is error (DN-012); **seed source**: a named place a recorded location came from: the agency's own developer page, catalog.data.gov, api.data.gov, this repository's citations, or a model's knowledge, each recorded per location; **params.***: a named parameter in the harness's configuration file (assessment/harness/scan/params.yaml); its value is stated where it matters.
