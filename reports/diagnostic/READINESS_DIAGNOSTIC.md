# A readiness diagnostic of federal statistical websites: what the public client is, and what it never does

Generated by `scripts/diagnostic_package_build.py` from the framework record, the measurement frame and the cycle of record `scan_2026-10-07_composite_d`, under DN-016. The run is a *readiness diagnostic*; its unit is a *check*; the client that runs it is the *public client*.

## The public client, and what it never does

This is a readiness diagnostic: 16 checks run against the public websites of 16 federal statistical bodies, with 3 reference hosts shown beside them, over a named roster of 72 surfaces. Each check is one published question about whether a machine client can reach, read and use the data. The thing that runs the checks is the public client: the least privileged client a member of the public has.

**How it behaves.**

- The public client identifies itself in every request by one fixed user-agent string, so a security team can find every request it made in its own logs.
- It makes one request per check per surface. It holds to 1 request per second per host, and it waits longer when a host's robots.txt asks it to, up to a ceiling of 60 seconds, above which it records the surface as not measured rather than press on.
- It honours robots.txt. On the cycle of record it did not fetch 16 surfaces because the host's robots.txt told it not to, and it recorded those as not measured.
- At the first rung it presents no credentials of any kind. At the second rung it presents only a key obtained by open public registration.

**What it never does.**

- It submits no form and solves no challenge: no CAPTCHA, no sign-in, no search box filled in.
- It runs none of a page's scripts; it reads the page as first served.
- It fetches nothing beyond a page's own headers and its body: no files a script would build, no addresses reached only through a tool.
- It takes no credential a citizen cannot obtain. A rung that needs an agency to grant what a citizen cannot get for themselves is reported as not measured, refused — never scored.

It identifies itself as `ai-readiness-kg-scanner/0.2 (+https://github.com/brockwebb/ai-readiness-kg)` (`assessment/harness/scan/params.yaml` line 144).

**The four states.**

A check comes back in one of four states. A pass means every one of the agency's data pages that was looked at met the check; a fail means every one did not; a partial means some met it and some did not; and not measured means the public client could not look at one or more pages, so that neither "every page passes" nor "every page fails" is established. Not measured has three reasons: the host refused the identified client; the client's own robots.txt compliance kept it from reading the page; or it could not confirm an absence, or a server or network error stopped it. Not measured is never a fail.

**The two rungs.**

The public client runs on a ladder of two rungs. Rung one is anonymous and keyless: it honours robots.txt and holds to the standing rate limit. Rung two is the same client registered as any member of the public registers, presenting a key obtained by open registration — a good-faith handshake, not a barrier. A refusal at rung one with a pass at rung two is reported as both, because both are true about the public experience. Rung two is specified here and measured in its own later cycle; no rung-two result is shown before one exists.

**What this is not.**

This diagnostic does not test whether an agent completed a task with the data; that is a later level of the framework, not this one.

**Not a league table.**

This is not a public league table, and it is not a campaign to make any agency open its site to anyone. The results go to the agency, not to the public. A check that rests on a rule this project chose rather than on a published standard is shown for transparency and is not scored as a finding about the agency; the method is published here in full so that a reader can see exactly what was and was not measured, and argue with it.

**A few terms.**

- **media type** — the short label a web server sends with a file to say what kind of file it is, such as a spreadsheet, a CSV or a PDF.
- **a page that reports success for an address that does not exist (a soft error page)** — a server answering a made-up web address with a normal page instead of a clear not-found message, so a machine cannot tell the address is wrong.
- **OpenAPI or Swagger description** — a machine-readable file that lists an interface's available calls, so a program can use the interface without a person reading the documentation first.
- **kibibytes** — a unit of file size, close to a kilobyte; used here as a small floor so a stub file is not mistaken for a whole download.
- **a recognised licence identifier** — a licence named by a standard short code from a public list, rather than described only in a sentence, so a machine can tell the terms of reuse.
- **a sitemap** — a file a site publishes that lists its pages, so a machine can find them without following every link.
- **robots.txt** — a file at the top of a site that states, as a policy, which automated clients the site asks to fetch which paths.
- **a structured change feed** — a machine-readable list of what changed between releases, in a common subscription format, rather than a change note written only for a person to read.
- **a surface** — one web address the diagnostic looks at: a data page, a home page, an interface address, or a well-known path.
- **a rung** — one of the two levels of the public client: the first without any key, the second with a key obtained by open public registration.
- **a dataset's release markup** — fields embedded in a page that state, for a machine, when the data was published or last changed.

## The dictionary: sixteen checks

### Page links a structured data file

- **How this check counts.** Scored: a pass or fail here is a finding about the agency.
- **The question.** Is the data offered in a structured, machine-readable file a computer can read directly, such as CSV, JSON or a spreadsheet, rather than only as a PDF that has to be re-parsed?
- **Where we look.** On the agency's data page, and the files linked from that page that sit on the same website as the page itself.
- **What the client does.** The public client opens the data page and then, for each file linked on it that lives on the same website (up to twenty-five), makes one quick web request asking the server what that file is, at a pace of one request per second.
- **What passing looks like.** A link on this data page, on the page's own website, returned a file that the server labeled by its media type, or the address named by its file extension, as a structured data format: CSV, JSON, XML, spreadsheet or Parquet. Every data page that was looked at met this.
- **What partial, fail and not measured look like.** Partial — Some of the agency's data pages linked such a structured file and some did not. Fail — Every linked file on the same website, in the page's HTML as first served (files built by scripts or reached through a form are not seen), was checked, and none was labeled by its media type or its file extension as a structured data format. It is not a claim that the page links no structured file at all (a real data file served with a generic label and no extension is missed), nor that the agency publishes no machine-readable data: data offered on another website, such as a data portal or an API, or reached only through a query tool, is outside this page's same-website links. Not measured — The public client could not look at one or more of the linked files, for one of three reasons: the host refused the identified client; the client's own compliance with the site's robots.txt kept it from the file; or it could not confirm the absence because the page carried more same-website links than the cap of twenty-five, or a server or network error occurred.
- **Why it matters.** USAFacts' AI-ready data guide says to publish datasets in common structured formats (JSON, CSV, machine-readable Excel) and avoid PDFs, an OMB memo requires public data assets to be machine-readable, and a Data on the Web Best Practice asks for a machine-readable standardized format.
- **Who else runs this check.** Google Lighthouse runs this kind of check: anyone can run its automated checks against a named page, its criteria are published, and a result comes back met, not met, or not applicable. It does not run this exact one.
- **What rung two changes.** Nothing: this check needs no key.

- **The question.** Can the whole dataset be retrieved in a single request, rather than assembled piece by piece from many filtered queries?
- **Where we look.** On the agency's data page, and the files linked from that page that sit on the same website as the page itself.
- **What the client does.** The public client opens the data page and then, for each file linked on it that lives on the same website (up to twenty-five), makes one quick web request asking about that file's type, its size, and whether its address carries a query, at one request per second.
- **What passing looks like.** This data page links, on its own website, an archive file (named by its extension) or a file that is not a web page, carries no query in its address, and is at least fifty kibibytes. It is not verified to be the complete product. Every data page that was looked at met this.
- **What partial, fail and not measured look like.** Partial — Some of the agency's data pages linked such a whole-product download and some did not. Fail — Every linked file on the same website, in the page's HTML as first served (a download behind a script-driven button or a form is not seen), was checked, and none is an archive or a non-web-page file without a query of at least fifty kibibytes. Not measured — The public client could not look at one or more of the linked files, for one of three reasons: the host refused the identified client; the client's own compliance with the site's robots.txt kept it from the file; or it could not confirm the absence because the page carried more same-website links than the cap of twenty-five, or a server or network error occurred.

### The site's sitemap lists the data page

- **How this check counts.** Scored: a pass or fail here is a finding about the agency.
- **The question.** Is the agency's data page listed in a sitemap served on the agency's own website?
- **Where we look.** The sitemap files at the standard locations on the agency's own site (a sitemap, a sitemap index, and any sitemap the site's robots.txt names on that same site), plus an llms.txt and the well-known discovery paths.

- **What passing looks like.** Every data page looked at was found listed: a sitemap served on the agency's own site carries the page's address exactly as the diagnostic records it.
- **What partial, fail and not measured look like.** Partial — Some of the agency's data pages are listed in a served sitemap and some are not.
