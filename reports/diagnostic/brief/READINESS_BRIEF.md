# A readiness diagnostic of federal statistical websites

*Brief for the working group, 16 October 2026*

Generated by `scripts/readiness_brief_build.py` from the framework record, `reports/summary/grid.json` and the cycle of record `scan_2026-10-07_composite_d`.

## Why

**No new burden.** The diagnostic uses what agencies already publish on their public websites. It needs no survey, no data call and no agency staff time.

**The public data user is the customer.** A machine is now one of the main ways members of the public reach federal data, so the diagnostic takes the machine's view as the public's proxy, to show what their experience is and how it could improve.

**Anyone can do this.** Any member of the public with a laptop can make the same requests. The diagnostic writes the questions and the method down, so the answer does not depend on who asks.

## Who

The public client is the program that makes the requests, acting only as any member of the public could. It identifies itself by one fixed name in every request, so a site's own logs show each request it made:

`ai-readiness-kg-scanner/0.2 (+https://github.com/brockwebb/ai-readiness-kg)`

The name still carries the project's earlier word for the client; it is kept unchanged so that one log search finds every request.

It makes no more than 1 request per second to any one website, and waits longer when a site asks it to.

## What the public client never does

- No sign-in or password.
- No form filled in.
- No "are you human" test passed, and no block worked around.
- No program built into a page is run.
- Nothing taken beyond what the page itself serves.

Not measured means the client could not look, and the footnote says why. It is never counted as a fail.

## The checks

The diagnostic runs 16 checks. Of these, 4 are scored; the rest are shown so the method is open, and produce no finding about an agency.

| Check | What we ask your site for | What it tells us | Why it matters |
|---|---|---|---|
| **Accessible** | | | |
| Data offered as a file a program can read (Scored) | The data page, and the files it links to on the same website. | Whether the numbers come as a spreadsheet, CSV or JSON file, not only as a PDF. | An OMB memo requires public data to be readable by programs, and USAFacts' guide says to avoid PDF-only release. |
| The whole dataset in one download (Scored) | Links on the data page to one zipped or complete file holding the whole dataset. | Whether someone can take all of it at once instead of piecing it together query by query. | The World Wide Web Consortium's data guidance asks that a full dataset come in one request, and an OMB memo urges offering whole datasets for download. |
| The data page is in the site's list of pages (Scored) | The site's list of its own pages (its sitemap), which search engines routinely ask every site for. | Whether the agency has listed the data page among the pages it wants found. | An OMB memo asks agencies to publish such lists, in the published standard format. |
| A published description of the agency's data service (Not scored, shown for openness) | The address of the agency's data service for programs, and any file kept beside it that lists the requests it accepts. | Whether a program can learn what to ask for without a person reading the manual first. | A World Wide Web Consortium practice asks for service details that programs can read; the required file format is this project's rule. |
| Whether the site's visitor rules let AI tools in (The site's own statement, not scored) | The site's instructions file for automated visitors (robots.txt), which search engines also request as a matter of course. | Whether those instructions let the tools behind AI search reach the data page. | An OMB memo tells agencies to use this file so pages can be found; treating certain blocks as failures is this project's rule. |
| The page labels itself as a dataset (Not scored, shown for openness) | The data page itself, reading the hidden labels that tell search engines what the page is. | Whether a search engine or AI tool can recognise the page as a named, described dataset. | A shared labelling scheme used by the major search engines (schema.org) defines these labels, and USAFacts' guide asks for standard metadata. |
| The release date, and a link to the latest release (Not scored, shown for openness) | Date labels in the data page's code, and up to three links that point to the latest version. | Whether a program can tell which release it is reading and find a newer one. | Guidance from the World Wide Web Consortium says a dataset's version should be detectable; requiring the link to work is this project's rule. |
| A front door built for programs (Not scored, shown for openness) | A few fixed addresses where programs look first, such as /llms.txt and the data service's description. | Whether the agency offers a starting point designed for software rather than for people. | This project's rule: no published standard defines such a starting point yet. |
| The interactive data tool answers honestly (Not scored, shown for openness) | A direct link into the agency's interactive data tool, and a made-up address beneath it. | Whether the tool returns real content, and a real "not found" for an address that does not exist. | An internet standard defines a "not found" answer; the minimum amount of readable text is this project's rule. |
| What the site states about automated access (The site's own statement, not scored) | The site's instructions to automated visitors, and the matching tags carried on the data page. | What the agency has put in writing about which automated visitors may read the page. | The internet standard for that instructions file says it is not a lock; this records a statement and is not scored. |
| The site serves what its own rules permit (Under review, not scored) | Those same visitor instructions, then the data page, both requested under one fixed name. | Whether the site actually delivers a page its own stated policy allows. | Comparing what a site says with what it does is this project's own idea, still under review. |
| From a data page to the data service, terms, change log and inventory (Not scored, shown for openness) | Links on one data page, and the known addresses of the agency's data service, its terms of use, its change log and its data inventory. | Whether a program that starts on a data page can find everything the agency offers for machines. | A web standard sets an address for listing data services, and an OMB memo fixes where the inventory lives; joining the four is this project's rule. |
| **Understandable** | | | |
| The methods are readable as plain text (Not scored, shown for openness) | The data page and up to twenty-five of its links that mention methodology. | Whether a program can read how the numbers were made without running the programs built into the page. | A published documentation guide asks that methods be reachable by automated visitors; the no-scripts reading is this project's rule. |
| **Open** | | | |
| The product is listed in the agency's data inventory (Scored) | The agency's public data inventory file, called data.json, at each address on record for it. | Whether the product has a valid entry there, so a catalog can find it. | An OMB memo requires every agency to keep a complete data inventory at that address. |
| The terms of reuse, under a recognised name (Not scored, shown for openness) | The licence named in the page's own description and, where one exists, the data service's terms page. | Whether a program can tell, from a standard licence name, how it may reuse the data. | The web's standards body asks for a stated licence; demanding a standard licence identifier is this project's rule. |
| **Release** | | | |
| A change history a program can follow (Not scored, shown for openness) | The agency's change log or release notes, at each address on record. | Whether software can see what changed between releases from a structured list of changes. | The World Wide Web Consortium asks publishers for a full version history; requiring it in a fixed structured form is this project's rule. |
