# Readiness diagnostic: what it measures, at a glance

Generated by `scripts/readiness_rollup_build.py` from the framework record and the cycle of record.

The readiness diagnostic checks whether a program acting for a member of the public can get an agency's data and the documentation that goes with it.

Its checks descend from the four criteria of the USAFacts guide to AI-ready data; the diagnostic measures the criteria that can be measured from outside and adds one check from release practice.

| Criterion | What the framework asks for | Checks | Quality concern | Agencies passing every check in this bucket^a |
|------------|--------------------------|----------------------------------|----------------|--------------------|
| Accessible | Data Must Be Machine-Readable and Easy to Access | Twelve checks: Data offered as a file a program can read (Scored); The whole dataset in one download (Scored); The data page is in the site's list of pages (Scored); A published description of the agency's data service; Whether the site's visitor rules let AI tools in; The page labels itself as a dataset; The release date, and a link to the latest release; A front door built for programs; The interactive data tool answers honestly; What the site states about automated access; The site serves what its own rules permit; From a data page to the data service, terms, change log and inventory | Find and obtain; understand; usable format; metadata | two of sixteen |
| Understandable | Data Must Be Machine Understandable with Easily Retrievable, WellStructured Documentation and Metadata | One check: The methods are readable as plain text | Understand | two of sixteen |
| Accurate | Agencies Should Provide Clear Evaluation Benchmarks and Make Them Public | None |  | no check yet; needs an evaluation harness |
| Open | Data Must Be Unencumbered and Open to All Citizens | Two checks: The product is listed in the agency's data inventory (Scored); The terms of reuse, under a recognised name | Find and obtain; metadata | zero of sixteen |
| Release engineering (added) | Pre-release gates, contract stability, vintage-transition regression, change legibility, staged rollout, release authenticity. | One check: A change history a program can follow | Metadata | zero of sixteen |

^a An agency passes a bucket when none of the bucket's checks that could be measured for it comes back fail; a check not measured for an agency, or not measured on the cycle of record at all, is left out of that agency's count and is never read as a fail.

Checks descend from USAFacts (2026), *AI-ready data*; concerns from FCSM 20-04, Accessibility dimension, after Webb 2026.

Standard user: no key. API user: a free key by open registration, a person completes an email step.
